# results/

`<project>.json` are the development set's scan results (`scan-all.mjs`, written by the 0.188.0 engine; they are the stored "after" of the first
precision work and are not regenerated by every change).

## reach-crosstab.json: the gate on caller-aware reachability (0.189.0)

`reach-crosstab.mjs` cross-tabulates `finding.reachability.status` against every hand label of the development set (`labels.json` and
`labels-remainder.json`) and the fresh set (`fresh-labels.json`). The rule, fixed before it was run: **if one site labelled a true positive lands in
`unreachable-in-project`, the mechanism is wrong and does not ship.** It exits 1 in that case.

Produced by `scan-all.mjs` over both sets with the 0.189.0 engine, then:

    node bench/dag/dev-haskell/reach-crosstab.mjs <dev results dir> <fresh results dir> --write bench/dag/dev-haskell/results/reach-crosstab.json

All 345 labelled sites:

| status | true positive | false positive |
| --- | --- | --- |
| entrypoint-reachable | 8 | 58 |
| external-api | 0 | 35 |
| unknown | 0 | 2 |
| unreachable-in-project | 0 | 0 |
| no verdict (rule findings, which have no call-graph function) | 14 | 131 |
| not reported by the engine | 4 | 93 |

**Result: nothing landed in `unreachable-in-project`, true positive or not, so the gate passes trivially.** Read that for what it is. It does not
show the mechanism is right; it shows it did not fire at any labelled site, which means it also did not remove a single false positive. The reasons
are structural and visible in the same run: most of these projects contain Template Haskell (a project-wide `opaque-boundary`, by design), several
use an hpack library that exposes every module, `cabal2nix` overrides its entry point, and the libraries (xmonad-contrib, scotty, hlint) expose their
modules, so their functions are `external-api`. Of the 14 projects only gitit has a hole-free call graph; a standalone IR run on it (which does not model the scan's path-policy gaps) puts 43 functions in
`unreachable-in-project`, none of which is a labelled finding site. The 4 true positives "not reported" are the four the 0.188.0 work already lost
(`fresh-score.mjs` lists them); the reachability pass did not change which findings exist.
