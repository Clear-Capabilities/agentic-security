# scanner/

Node-only scan engine. ESM throughout, Node ≥ 24. The CLI bundle (`dist/agentic-security.mjs`) is built from `bin/agentic-security.js` and committed; the `src/` tree is what tests run against.

## Build invariants

- After **any** change to `src/` or `bin/`, run `npm run build` before relying on the bundle. `bin/` is the test entry point and re-imports `src/` directly, so unit tests don't require a rebuild — but anything calling the bundle (the CI gate, hooks, the published `npx` command) will be stale until you rebuild.
- The build is `ncc build … --minify`. Output is a single ESM file plus a SHA-256 sidecar. The hashing step is part of `npm run build`; do not commit the bundle without it.
- `chmod +x` is part of the build. If a `permission denied` shows up on `node dist/agentic-security.mjs`, rerun the build — somebody copied the file and lost the bit.
- **Running the CLI locally (not via `npx`).** `node @clear-capabilities/agentic-security-scanner ...` does not work — `node` resolves a literal file/directory path, not an npm package name; that resolution is what `npx` (and the installed `agentic-security`/`as` bin aliases) does. From `scanner/`, either:
  - `node dist/agentic-security.mjs <command> …` — runs the built bundle directly (rebuild first if you've touched `src/` or `bin/`, per above), or
  - `npm link` once, then use the bare `agentic-security` / `as` commands, which resolve to this checkout.

## Test commands (scoped, premortem-derived)

`npm test` is the full CI gate — `scripts/run-unit-tests.mjs` runs the scoped scripts below in ONE `node --test` invocation over their combined file list (derived from the scripts themselves, not hand-duplicated) rather than eleven separate processes, plus `test/cpp-dataflow.test.js` and `test:python` as their own steps afterward. For day-to-day work, use the scoped variants below individually — they're faster for one area and avoid blowing the context window:

| Script | Covers | When to run |
|--------|--------|-------------|
| `npm run test:smoke` | The end-to-end vulnerable-js fixture (~13 s: it runs a real scan, so it is the cheapest MEANINGFUL check, not an instant one) | After any change anywhere |
| `npm run test:sast` | Detector modules in `src/sast/` | When editing a SAST rule |
| `npm run test:posture` | Posture modules in `src/posture/` | When editing a posture annotator |
| `npm run test:dataflow` | IR, taint engine, calibration, held-out evaluator | When editing `src/dataflow/`, `src/ir/`, or calibration |
| `npm run test:mcp` | MCP server tools + audit log | When editing `src/mcp/` |
| `npm run test:report` | Report emit (SARIF/JUnit/CI/PoC/verifier) | When editing `src/report/` |
| `npm run test:lineage` | `src/lineage/` — DataFlowGraph v1 contract, IDs, fixture | When editing `src/lineage/` |
| `npm run test:server` | `src/server/` — the `explore` loopback HTTP server (graph-loader, security, routes, http-server) + `bin/agentic-security.js`'s `cmdExplore` and `cmdDataflowExport` | When editing `src/server/`, or the `explore`/`dataflow export` CLI commands |
| `npm run test:verification` | `test/verification/` — the one verification record, the oracle adapters and replay manifests (runs targets through the trust boundary; the execution tests skip, loudly, where the boundary cannot run) | When editing `src/posture/{verification,oracles,replay}/` |
| `npm run test:lifecycle` | Dead-code + dead-module guards | Before committing a remediation that adds new modules |
| `npm run test:haskell` / `test:nix` / `test:language` | Haskell, Nix/NixOS and language-wide suites (part of `npm test`) | When editing `src/language/` |
| `npm run test:language-stress` / `test:language-tools` | Scale/memory suite; criteria that need `ghc` (both excluded from `npm test`, see `scripts/run-unit-tests.mjs`) | Before a release; where the tools exist |
| `npm run bench:language-support:check` | Haskell/Nix support registry vs the stored measurement | After touching `src/language/` or the corpus |
| `npm run smoke` | One-shot: run the CLI against the vulnerable-js fixture | Sanity-check the bundle |

Every test file under `test/*.test.js` should be assigned to one of these scoped scripts. If you add a new test file, also add it to the matching script in `package.json` — `npm run test:lifecycle` will warn if a new module ships without a wire-up, but it won't catch tests dropped from scope.

## Key conventions

- **Findings schema** — `{ id, severity, file, line, vuln, cwe, description, remediation, parser, family, … }`. `parser` + `family` are required; `posture/finding-defaults.js` backfills before confidence/calibration so detectors that forget to set them still calibrate correctly.
- **No runtime cloud calls** — OSV/KEV data is fetched lazily and disk-cached under `~/.claude/agentic-security/osv-cache/`. Anything new that needs the network must be opt-in and degrade gracefully when offline.
- **`scan.findings` is the SAST array.** Secrets live on `scan.secrets`, supply-chain on `scan.supplyChain`, business-logic on `scan.logicVulns`. The report `normalizeFindings` merges them; engine code should keep them separate.
- **Suppression pragmas** — `// agentic-security-ignore: <rule-id>` on the offending line suppresses that rule for that line. `_applyIgnorePragmas` runs twice in `engine.js`: once after the cross-file passes, once after the deep-mode IR append. If you add a stage that appends findings, it must run after your stage too, or pragmas will be inert for whatever it produces. A finding with no integer `line` cannot be suppressed at all — see the root `CLAUDE.md` bullet.
- **Determinism** — `--deterministic` and `AGENTIC_SECURITY_LLM_VALIDATE` should produce byte-identical SARIF run-to-run. Sort outputs before emit; never use `Date.now()` in a finding ID.

## Subdirectory pointers

- `src/sast/CLAUDE.md` — how to add a new SAST module (was previously in root)
- `src/posture/CLAUDE.md` — what each module category is for (90+ modules, indexed there)
- `src/dataflow/CLAUDE.md` — k=1 monovariant scope, `SummaryCache` keying, what the engine does NOT model
- `src/language/CLAUDE.md`, **start here for Haskell and Nix/NixOS**: invariants, module map, test scopes, how the support registry and the generated docs work. The bullets below are the per-module detail.
- `src/language/discovery.js`, shared Haskell/Nix discovery registry (sources, manifests, explicit exports, build/store exclusions, bounded import graph, per-file invalidation digests). Used by `runScan.js`, `engine.js` (`shouldScan`, checkpoint key) and `posture/watch-mode.js`. Explicit Cabal plan/Stack/Nix exports are read by exact path only; `dist-newstyle/`, `.stack-work/`, `.cabal-sandbox/`, `.direnv/` and `nix/store/` are pruned from the walk (the one documented change to existing walk behaviour). Suite: `test/language/language-discovery.test.js`.
- `src/language/contracts.js`, Haskell/Nix pipeline contracts (CORE-003): optional `language`/`capability`/`evidenceKind`/`scope`/`uncertainty`/`originalLocation` finding and component metadata (legacy required fields unchanged), a language producer registry mirrored into `pipeline/producer-registry.js` (results from an unregistered producer are discarded and reported, never silently counted), and `runLanguageAnalysis`/`reconcileLanguageLedger`/`languageHealth`, which record per-file, per-analyzer analyzed/excluded/unresolved/failed/timed_out/missing_grammar outcomes and feed `computeScanHealth`'s optional `languageCoverage` input. Suite: `test/language/language-contracts.test.js`.
- `src/language/haskell-parser.js` + `haskell-grammar.js` + `haskell-adapter.js`, Haskell parser with original source locations (HS-001). Dependency-free lexer, layout resolver and extractor over the shipped, SHA-256-pinned grammar tables (`loadHaskellGrammar` returns a `missing-grammar`/`corrupt-grammar` gap instead of throwing). Preprocessing (literate Bird/LaTeX, CPP, hsc) overwrites with same-length spaces, so spans (`startLine`, 0-based UTF-16 `startColumn`, UTF-8 `startByte`, exclusive ends) index the ORIGINAL file. Comment/string/quasi-quote text never becomes tokens; a top-level declaration with a syntax error withholds its calls and the error records how many. TH/quasi-quote/FFI/hsc/CPP/generated boundaries are disclosed, never executed. Bounded by `DEFAULT_PARSE_BUDGETS` (a hit returns `budget_exceeded`, no throw). The adapter feeds `runLanguageAnalysis`, so syntax errors and opaque boundaries become `unresolved` outcomes in scan health. Suite: `test/haskell/haskell-parser.test.js`.
- `src/language/haskell-resolved-graph.js`, resolved Haskell dependency graph (HS-008). Reads an EXPLICIT cabal plan export (`planPath`) or Stack resolved export (`stackExportPath`), never discovers or runs anything, and joins it to the HS-007 declared inventory. Units are keyed by unit id (flag variants stay distinct), labelled `local`/`hackage`/`compiler`(boot)/`vcs`/`url`/`unknown`, with runtime/test/benchmark/setup/build-tool scopes propagated along edges. A plan is checked for freshness (compiler, flags, local packages/versions, declared bounds, targets, mtime); stale means downgraded (no versions copied into the declared inventory, no complete closure) or dropped with `rejectStale`. Freeze/lock alone is `lock_only`, never a closure. Missing data leaves `units`/`edges` null (unknown), not empty. Suite: `test/haskell/haskell-resolved-graph.test.js`.
- `src/language/nix-parser.js` + `nix-grammar.js` + `nix-ir.js` + `nix-adapter.js`, Nix parser and bounded config IR (NIX-001). Dependency-free lexer/parser over shipped, SHA-256-pinned grammar tables (a missing or tampered table is a `missing_grammar` gap, never a throw); never runs `nix`. Spans index the ORIGINAL file (1-based lines, 0-based UTF-16 columns, UTF-8 bytes). Strings and paths are text/interp parts, so `literal` is null whenever there is interpolation; comment and string text is never a binding. The IR flattens attribute paths (merging `a.b = ..` / `a = { b = ..; }`, `//`, `mkMerge`, `mkIf`, priority wrappers), and exposes imports, flake inputs/outputs, overlays and functions. Dynamic attributes/imports, import cycles, lazy recursion, syntax errors and parser/IR budget hits become `unresolved` entries (status `partial`), never silent drops. A syntax error inside one binding withholds only that binding. Parser budgets (`DEFAULT_PARSE_BUDGETS`, including nesting depth, which atoms count toward) return `budget_exceeded`. Suite: `test/nix/nix-parser-ir.test.js`.
- `src/language/nixos-module-resolver.js` + `nixos-option-catalog.js`: bounded effective NixOS / Home Manager configuration reasoning (NIX-002). `resolveNixosConfig({entry, files|root|readFile, target, flake, catalog, budgets})` follows literal local imports only (never `nix`), then decides each option by module-system priority (mkForce 50, plain 100, mkDefault 1000, mkOverride N literal), `mkMerge`, and `mkIf`/`if` conditions judged by a small evaluator (booleans, `!`/`&&`/`||`/`==`, `config.<option>` and let-aliases, `pkgs.stdenv.isLinux` from `target.system`, `target.args`). An undecidable condition keeps the value `conditional`; equal-priority disagreement is `conflict` (typed) or `unresolved-precedence`; nothing is guessed. A missing setting gets a default only when the catalog proves it for the release in force (or identically for every cataloged release), else `unknown`. The release comes from `target.release` or a flake `nixpkgs` input, never `system.stateVersion` (reported separately as a compatibility marker). Each option result carries target, per-source file/span/priority/condition outcomes, precedence rule and catalog revision, plus `caveats` (dynamic attributes, opaque parents, overlays, unknown options in a cataloged namespace, partial module graph) that clear `definite`. Renames are evaluated under the current name; unknown options in an authoritative namespace are listed and withhold a definite default. Home Manager is a separate namespace scoped per user. Caps (`DEFAULT_RESOLVE_BUDGETS`) and cycles end as `unknown` plus `truncated`/`unresolved`. Catalog is pinned by release and content hash (`catalog.revision`), not by nixpkgs commit. Suite: `test/nix/nixos-module-resolution.test.js`.
- `src/language/nixos-hardening.js`: NixOS service, access and host hardening rules (NIX-004). `analyzeNixosHardening(opts)` judges the NIX-002 effective config (never raw text) against 17 versioned rules (`HARDENING_RULES`, ruleset `nixos-hardening/1`): SSH root/password/empty-password, firewall disabled and sensitive ports, all-interface listeners and trust auth, service identity and elevated `ExecStart`, systemd capability/device/filesystem/NoNewPrivileges, sudo/doas, disabled TLS verification env, and OCI container declarations (declarations only, `imageLayerScan: 'not-performed'`). Enabled, listening and reachable are separate: reachability is always `unknown` (only the host firewall is modelled, as `ingress`). Findings from a conditional state, a partial module graph or a non-definite value are capped at `medium`; inactive or absent services never produce findings; renamed options are judged under their current name. The report carries `inventory`, `privilegedEntryPoints`, `authzEvidence`, `attackPaths` and a `reconciliation` (active/conditional/inactive counts, unanalyzed gaps). Finding `subject` is the rule's target (`scope` is the contract's `system`). Suite: `test/nix/nixos-hardening.test.js`.
- `src/mcp/CLAUDE.md` — MCP tool inventory, OWASP MCP Top 10 mapping, reserved-write list

## LSP for self-development

The bundled LSP at `bin/agentic-security-lsp.js` ships to **users** for inline findings in their editors. It is not currently part of the development loop for this repo — Claude Code and the scanner test suite already cover internal needs. If you want to dogfood it, run `node bin/agentic-security-lsp.js` and point your editor's LSP client at it, but this is not a documented or supported workflow for contributors yet.
