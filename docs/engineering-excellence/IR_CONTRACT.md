# IR and dataflow contract (E2-01)

Part generated by `node scripts/engineering-excellence/ir-matrix.mjs`, part written. The matrix below is measured; the rest is the contract the new semantic graph adds.

## Layers

| Layer | Where | What it holds | Consumers |
|---|---|---|---|
| Layer 1: per-file IR | `scanner/src/ir/parser-*.js`, `index.js` | per function: `qid`, `name`, `line`, `params`, a CFG, `calls[]` (statement-level calls), `writes{var:[{node,source}]}` (assignment sources as expression trees), `returns[]`; per project: a call graph and a class hierarchy | the taint engine, reachability, the DCI symbol graph (separately) |
| Layer 2: dataflow | `scanner/src/dataflow/` | k=1 monovariant return-taint, summaries, access paths, points-to, guard dominance, sanitizer gates, path feasibility, symbolic execution, cross-service taint | `ir-taint` findings and their `chain[]` |
| Layer 3: validation | `scanner/src/llm-validator/` | optional model judgement over a finding | confidence only |
| **Semantic graph (new, additive)** | `scanner/src/ir/semantic-graph.js` | typed entities with stable ids over Layer 1, see below | none yet; opt-in |

## Known structural gaps in Layer 1 (observed, not inferred)

- A call nested inside an assignment source (`const cmd = h.build(x)`) is recorded under `writes`, not in `calls[]`, so a consumer that reads only `calls[]` misses it. The semantic graph reads both.
- `exports.run = function run(){}` records the assignment source as `unknown`; the function itself is a separate record, and nothing links the export name to it.
- The call graph has no edge for `h.build(...)` where `h` is a `require` result: the callee is `null`. Cross-file resolution is E2-02.
- The IR carries line numbers only, never columns.

## The semantic graph contract

`buildSemanticGraph(projectIR)` returns `agentic-security/semantic-graph` version `1.0.0`. It is additive: it reads the IR, never changes it, and is not part of findings, `chain[]` or `last-scan.json`.

| Entity list | Populated from the IR today | Identity (never includes a line) |
|---|---|---|
| `symbols` | yes: modules and functions | file, qualified name without the `@line` suffix, order among same-named |
| `callSites` | yes: `calls[]` plus calls inside assignment sources | caller symbol, callee text, order within the caller |
| `allocations` | yes: object, array and function-valued expressions | owning symbol, kind, order |
| `fieldAccesses` | yes: member reads and dotted writes | owning symbol, base, path, mode, order |
| `valueOrigins` | yes: every call argument and every assignment source | owning symbol, variable, origin kind, text, order |
| `serviceBoundaries`, `storageEdges` | schema only: the IR carries none; E2-07 | |
| `sanitizers`, `guards` | schema only: decided by the dataflow layer, not recorded; E2-08 | |

Every entity has `file`, `line`, `column` (always `null` today, with `locationPrecision: "line"`) and `confidence: { tier, basis }` where tier is `observed`, `inferred` or `unresolved`. A call resolved only by a same-file name match is `inferred`; an unresolved call says so and has no callee. The `coverage` block says, per list, `populated` or `schema-only` and why. The wire format is canonical JSON (sorted keys, entities sorted by id); a different major version is refused, not guessed at, and `migrateGraph` brings an older minor up to date.
