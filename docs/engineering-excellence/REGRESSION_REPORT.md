## 7. Privacy hardening

Before: hostile repository text was assumed not to act. After: a test builds a repository where every attacker-controlled surface tries to run a command, open a connection or write a file, runs the real CLI under an observer, and checks what happened; a negative control proves the observer sees such calls. The boundaries and the tests that hold them are listed in `ADVERSARIAL_BOUNDARIES.md`. Runtime records pass a canary scan and drop unlisted fields before they are stored, and collection is off until a policy file switches it on (shown in the end-to-end demo).

## 8. Evidence coverage

Before: evidence existed as separate files with no shared contract. After: 16 registered evidence kinds, each with a schema, an identity rule and a snapshot rule (`EVIDENCE_CONTRACTS.md`); the end-to-end demo's signed package carries 4 of them (finding, fix-verification, runtime-explanation, scan-health). The remaining kinds are registered and tested but not produced by the demo.
