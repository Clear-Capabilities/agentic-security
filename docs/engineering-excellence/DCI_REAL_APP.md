# Deterministic context analysis on application-shaped authorization cases (E4-06)

Generated by `node bench/dci-real-app/runner.mjs`; checked by `--check`. The cases are in `bench/dci-real-app/cases.mjs`.

## Read this first

- **Who labelled the cases:** the author of the cases, not an independent reviewer; no case is from an upstream advisory; all are synthetic. The PRD asks for labels from an independent reviewer or an upstream advisory; this corpus does not meet that. Treat every number below as a measurement on 21 small hand-written applications, **not** as accuracy on real software.
- Each route is labelled `vulnerable` or `safe` from what the code means, and the labels were fixed before the run. A `safe` route is either the fixed twin of a vulnerable one or a deliberately non-obvious counterexample (a control applied somewhere a simple scan does not look).
- A route the analysis could not settle is counted as `unresolved`, which is neither a hit nor a miss; precision and recall are over the settled routes. Nothing was dropped from the denominators.

## Families the analysis cannot represent

- **state-machine-bypass:** the context analysis has no extractor for workflow order or state transitions (the E4-01 audit marks workflow-state-check absent); a case could only be answered by a model-assisted pack, which has no measured accuracy.
- **race-toctou:** a check-then-act race is a property of interleavings, not of one handler's text; no deterministic fact or invariant expresses it.

## Confidence

Each count above is over a handful of routes, so no interval narrower than "could be almost anything" is justified; the per-family denominators are printed beside every rate so the size of the evidence is visible. No confidence interval is computed because the cases are not a random sample of anything.
